How I work

My QA approach

Testing should be systematic, explainable, and useful to the team. A green check mark alone is not enough.

01 / UNDERSTAND

Map the behavior

Understand requirements, user journeys, dependencies, and risks.

02 / DESIGN

Cover edge cases

Create positive, negative, boundary, and failure-path scenarios.

03 / EXECUTE

Capture evidence

Compare actual results with expected results and investigate failures.

04 / IMPROVE

Report and retest

Document defects, verify fixes, and improve regression coverage.
