My QA approach

I aim to make testing systematic, explainable, and useful to the team—not just a green check mark.

01 / UNDERSTAND

Map the behavior

Understand user journeys, expected outcomes, dependencies, and risks.

02 / DESIGN

Cover edge cases

Create positive, negative, boundary, and failure-path scenarios.

03 / EXECUTE

Capture evidence

Run tests and review failures, logs, coverage, and generated reports.

04 / IMPROVE

Protect delivery

Use CI checks and focused regression tests to catch issues earlier.
